重型电卡车-换电站-配电网协同调度优化模型
1. 概述
本构建了一个多阶段、多层次的仿真优化模型，旨在解决城市环境下，由重型电动卡车（HDT）组成的车队在执行物流配送任务时，与换电站网络及城市配电网之间的复杂协同问题。

其核心是探索物流需求如何以电力负荷的形式，通过换电站这一媒介，最终传导至配电网，并研究如何通过智能调度策略来优化整个系统的“物流-能源”联合效率。

整个工作流被设计为一个**“离线规划 + 在线修正”**的框架：

离线规划: 在一天开始前，基于预测数据，为整个车队制定一个全局最优的基础行驶路线和换电计划。

在线修正: 模拟在计划执行过程中，当出现电网过载等突发事件时，系统如何对单一车辆进行实时的路径调整。

2. 技术栈
核心语言: Python 3.8+

数学建模: Pyomo

优化求解器: Gurobi

数据处理: Pandas, NumPy

网络分析 (交通/电网): NetworkX, Pandapower

可视化: Matplotlib, Scipy

3. 安装与配置
3.1. 环境设置
建议使用 Conda 创建独立的 Python 环境。

Bash

# 创建一个新的 conda 环境
conda create -n hdt_env python=3.8

# 激活环境
conda activate hdt_env

# 安装所有必要的 Python 库
pip install pyomo pandas numpy matplotlib networkx scipy pandapower tqdm
3.2. Gurobi 求解器
依赖 Gurobi 作为核心的数学优化求解器。

安装: 需要自行从 Gurobi 官网下载并安装 Gurobi Optimizer。

许可证: Gurobi 是商业软件，需要有效的许可证。高校和学术研究机构通常可以申请免费的学术许可证。

关联: 确保 Gurobi 已正确安装并激活，Pyomo 能够自动找到它。可以在 Python 环境中运行 gurobi_cl --version 来测试安装是否成功。

3.3. 运行模式配置
支持两种运行模式，通过修改 main_two_stage.py 文件头部的开关来切换：

IS_QUICK_TEST = True: 快速测试模式。此模式会加载 src/common/test_config.py 中的小型测试场景（少量卡车和任务），并使用宽松的求解器设置。旨在快速验证整个代码流程的正确性，通常在几分钟内完成。

IS_QUICK_TEST = False: 完整求解模式。此模式加载 src/common/config_final.py 中的完整、庞大的场景，并使用严格的求解器设置以获得高质量的解。运行时间可能长达数小时。

4. 工作流详解
整个代码的执行逻辑被清晰地划分为多个阶段：

阶段 0: 场景生成 (loader_final.py)
在任何优化开始之前，程序首先会构建一个包含交通、能源、物流等元素的虚拟城市环境。

交通网络: 使用 NetworkX 生成一个随机几何图，模拟城市道路网络。节点间的距离和最短路径通过 Floyd-Warshall 或 Dijkstra 算法预先计算好。

配电网络: 使用 Pandapower 加载标准的 IEEE 118 节点测试系统，模拟一个真实的城市配电网拓扑。

设施布局: 将仓库（Depot）、客户（Customer）、换电站（SwapStation）等设施的地理位置随机映射到交通网络的节点上。同时，将每个换电站关联到配电网络的一个负荷节点（Bus）上。

任务生成: 根据配置，为车队生成一系列配送任务，每个任务包含起始仓库、目标客户、货物需求量（吨）和最晚送达时间（due_time）。

能源数据生成:

光伏(PV): 生成符合日照规律（中午高、早晚低）并叠加了随机噪声（模拟云层影响）的光伏出力曲线。

外部EV负荷: 生成符合城市充电习惯（早、晚双高峰）并叠加了随机性的外部电动汽车充电负荷曲线。

阶段 1 & 2: 离线路径规划 (run_greedy_insertion_stage2)
这是离线规划的核心。目标是为所有车辆制定一个全天运营的基础计划。

算法: 采用贪心插入启发式算法（Greedy Insertion Heuristic）。算法迭代进行，在每一轮迭代中：

从未分配的任务池中选择一个任务。

尝试将其插入到所有车辆现有路线的每一个可能位置。

评估每种插入方案所带来的成本增量。

可行性检查与决策 (check_route_feasibility):

这是贪心算法的“决策大脑”。对于每一个尝试性的插入，程序会调用此函数来评估其可行性与成本。

函数内部会构建一个完整约束的、小型的混合整数线性规划（MILP）模型 (model_final.py)。

此模型的目标是，在满足电池容量、最低SOC、时间窗、载重等所有物理约束的前提下，找到成本最低的行驶方案。

关键点: 模型中的swap_decision（换电决策）变量允许求解器为了维持电量可行性，而智能地决定是否需要在路途中访问换电站。

最终，贪心算法会选择那个能产生可行路径且成本增量最小的插入方案，并将其固化，然后进入下一轮迭代，直到所有任务都被分配完毕。

阶段 3: 能源系统调度与分析
在获得所有车辆的固定路线后，工作流进入能源分析阶段。

换电负荷聚合: 程序首先遍历所有车辆的最终路线，将在各个换电站发生的换电事件（由swap_decision变量标识）转换成对每个换电站在每个时间步（30分钟）的HDT电力负荷需求（hdt_swap_demand）。

单站能源优化 (station_energy_model.py):

为每一个换电站，独立求解一个线性规划（LP）模型。

目标: 在满足总电力需求（HDT负荷 + 外部EV负荷）的前提下，最小化其日运营成本（主要是购电成本）。

决策: 模型需要决定在每个时间步，应该从电网买多少电（p_grid）、用多少光伏（used_pv）、让自带储能充电（p_bess_ch）还是放电（p_bess_dis）。

鲁棒性: 模型包含了unmet_demand（未满足负荷）和p_pv_curtailed（弃光）两个松弛变量，以确保在需求过高或光伏过剩等极端情况下，模型仍然总能找到一个可行解，而不是直接崩溃。

阶段 4: 在线重规划模拟
这是对离线规划的一个补充和验证，用于展示系统应对突发事件的潜力。

事件触发: 在所有规划和分析完成后，代码模拟了一个实时突发事件。例如：“在上午8点，Station_1 所在的电网节点压力过大，该站临时关闭/换电成本激增”。

状态定位: 程序会检查原有的离线计划，找到在事件发生后，正准备前往Station_1的车辆，并获取它在事件发生时的当前位置、时间和SOC，以及它尚未完成的任务列表。

执行重规划 (replan_route_for_vehicle):

针对这辆受影响的卡车，程序会建立一个全新的、小规模的VRP模型。

这个模型的起点被强制设定为车辆的当前状态。

目标是仅对它剩余的任务进行最优路径求解。

动态约束: 根据事件信息，模型中加入了新的约束，比如“禁止访问Station_1”。

求解这个小模型会得到一条新的、避开了问题站点的、针对剩余任务的最优路径。

结果展示: 程序会打印出车辆的原始路线和重规划后的新路线，以对比展示在线修正的效果。

5. 如何运行
打开 main_two_stage.py 文件。

根据需要设置文件顶部的开关 IS_QUICK_TEST：

IS_QUICK_TEST = True：用于开发和调试，几分钟内出结果。

IS_QUICK_TEST = False：用于正式求解，获取高质量结果，耗时较长。

在激活了正确 Conda 环境的终端中，运行主文件：

Bash

python main_two_stage.py
等待程序执行完成。所有输出的日志会打印在控制台，所有生成的图表会保存在根目录下的 results/ 文件夹中。

6. 结果解读
程序运行结束后，检查 results/ 文件夹，你会看到一系列的分析图表：

fleet_routing_plan.png: 所有车辆的最终路线在城市地图上的宏观展示。

truck_analysis_[ID]_*.png: 每辆车的独立分析报告，包括其单独的路线图和“电量-载重”随时间变化的曲线图。

station_analysis_[ID].png: 每个换电站的详细能源调度图，展示了电网购电、光伏、储能、EV负荷、HDT负荷等功率曲线。

summary_fleet_performance.png: 车队整体性能仪表板，包含各车辆的行驶距离、时长、任务数和总成本构成饼图。

summary_task_delays.png: 任务准时性散点图，直观展示所有任务的送达是准时、提早还是延迟。

summary_station_network.png: 换电站网络的能源总结，包含各站的运营成本对比和整个网络的能源结构。

gantt_chart_[ID].png: 为最繁忙的几辆车生成的甘特图，详细展示了其一天中“行驶-服务-换电”的时间安排。
